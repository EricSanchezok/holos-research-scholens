# Lit Knowledge — Scholens Literature Workflow

> **User request:** $ARGUMENTS

## ⚠️ CRITICAL RULES

1. **Papers live in Scholens, never in `.research/literature/`.** This plugin has no local literature store. A legacy `.research/literature/` directory is read-only archive — do not write to it, index it, or migrate it automatically.
2. **Use the Scholens MCP tools directly** (`mcp__scholens__*`) for every literature operation — never invent local file paths for papers, metadata, or annotations.
3. **Bind the scope to a Scholens project first** and record the binding in `docs/scholens-project.md` (see § Bind Project).
4. **Surveys go in `docs/surveys/*.md`**; research gaps go in `docs/gaps.md`; both are plain markdown (agent-maintained, no tool/schema).
5. **Do NOT call research-output / data-table creation tools** (`mcp__scholens__list_research_output_summaries` etc.) — the server's output schema for those is unstable. Use papers, projects, annotations, citations, tags, and search only.
6. **Follow AGENTS.md at project root** — code discipline, directory structure, tool usage, naming conventions.
7. **End session with `research_state(action="brief")`** to update AGENTS.md dynamic state.
8. **Git commit research artifacts** (docs/surveys, docs/gaps) after modifying them.

---

## What This Skill Manages

Literature for a research scope is split across two stores:

```
Scholens project (cloud)                  scope root (markdown)
─────────────────────                     ───────────────────────
• papers: PDF, metadata, full text        docs/scholens-project.md  ← binding (id/title/url)
• ingestion: arXiv / DOI / URL / upload   docs/surveys/*.md         ← survey narratives
• annotations & discussion threads        docs/gaps.md              ← research gaps (G1..)
• library tags
• citation metadata
```

**Scope boundary**: This skill manages PAPER KNOWLEDGE via Scholens and the survey/gap markdown. It does NOT manage research ideas, plans, experiments, claims, exhibits, manuscripts, or submissions — those have their own tools under `.research/`.

**Requirement**: the host must have the `scholens` MCP server enabled (remote server configured with credentials). Before any literature step, verify the MCP tools are visible (e.g. `mcp__scholens__list_projects`). If Scholens is unavailable, state clearly that literature steps need the Scholens MCP and skip them — do NOT fall back to a local literature store.

## Bind Project (scope ↔ Scholens project)

Each research scope binds exactly one Scholens project. Project title = `state.project` (read via `research_state(action="overview")`).

1. **Look up**: `mcp__scholens__list_projects` — find an exact title match.
2. **Create** if missing: `mcp__scholens__create_project(title="<state.project>", description="<anchor>")`.
3. **Multiple matches**: pick the most recently updated; if genuinely ambiguous, list candidates and ask the user to choose.
4. **Record the binding** in `docs/scholens-project.md`:
   ```
   # Scholens Project Binding
   project_id: <uuid>
   title: <state.project>
   url: <web url if returned>
   updated: <ISO date>
   ```
5. **Re-verify each literature session**: re-run `list_projects`; reuse the binding when the title/id still match; rebuild the binding if the id is gone.

## DAG Template

```mermaid
graph LR
    load[Load Binding] --> search[Search Scholens]
    search --> ingest[Ingest Papers]
    ingest --> annotate[Annotate / Discuss]
    annotate --> writeback[Write surveys + gaps]
```

Nodes:
- `load` — read `docs/scholens-project.md`, verify with `list_projects`, reload state via `research_state(action="overview")`
- `search` — discover papers with `mcp__scholens__search_scholens_knowledge` (semantic search over stored papers/annotations) or `mcp__scholens__ingest_paper` for known arXiv/DOI/URL
- `ingest` — add papers to the project (see § Ingestion)
- `annotate` — highlight passages, add annotation threads
- `writeback` — persist survey notes under `docs/surveys/` and gaps in `docs/gaps.md`

## Skill Checklist

### Must
- Bind (or verify) the Scholens project before ingesting/searching; record in `docs/scholens-project.md`
- Ingest papers via `mcp__scholens__ingest_paper(s)` / `add_papers_to_project` — never write paper files locally
- Write survey narrative under `docs/surveys/`; maintain `docs/gaps.md`
- Record decisions in the journal via `research_journal(action="append", kind="decision_rationale", ...)`

### Forbidden
- Do NOT write anything under `.research/literature/` (legacy archive only)
- Do NOT save PDFs or `.bib` files into the research store — keep them in Scholens; generate manuscript `.bib` from `mcp__scholens__get_paper_citation` at compose time
- Do NOT use research-output / data-table / audio-overview tools (schema unstable)
- Do NOT silently double-write a paper both to Scholens and anywhere local

### Checkpoints
- papers_ingested (Scholens project has the papers; survey notes drafted)

## Tool Operations

### Ingestion

Prefer the bound project as the destination for every ingest:

```
mcp__scholens__ingest_paper(source={kind: "arxiv" | "doi" | "url", arxiv_id|doi|url: "..."}, project_id="<uuid>", add_to_library: false)
```

- Known identifiers → `ingest_paper` (arXiv id / DOI / URL)
- Batches of known papers → `ingest_papers` (1–50 sources)
- Paper already in your personal Library → `add_papers_to_project(project_id, document_ids=[...])`
- Local PDF → `prepare_paper_upload` (filename/size/sha256) then `ingest_paper(source={kind: "upload", upload_id})`; if the paper is a discovery target (no known id), search first — do not guess identifiers
- Duplicates are resolved server-side; a repeated ingest returns the existing document

### Search & Read

```
mcp__scholens__search_scholens_knowledge(query="...", scope={kind: "project", project_id: "<uuid>"})
mcp__scholens__list_project_papers(project_id="<uuid>", query="...")
mcp__scholens__get_paper(document_id="<uuid>")          # metadata + processing state
mcp__scholens__get_paper_content(document_id="<uuid>")  # extracted text (bounded pages)
mcp__scholens__get_paper_download_url(document_id="<uuid>")  # original PDF (short-lived)
```

Prefer `search_scholens_knowledge` for semantic questions across the project (papers + annotations). Use `list_project_papers` for a full inventory of the bound project.

### Annotate & Discuss

```
# NOTE: list_annotation_threads takes audience as a string plus a separate
# project_id (verified against the live server), unlike create_annotation_thread
# which takes the audience object:
mcp__scholens__list_annotation_threads(document_id="<uuid>", audience="project", project_id="<uuid>", status="open")
mcp__scholens__create_annotation_thread(document_id="<uuid>", quote_text="...", position={...}, audience={kind: "project", project_id: "<uuid>"}, initial_comment="...")
mcp__scholens__create_annotation_comment(thread_id="<uuid>", content="...")
```

Quote text must be exact visible paper text — never fabricate a quote. Use project audience for shared research context; library tags (`create_library_tag`, `replace_library_paper_tags`) for personal organization.

### Citation metadata (for manuscripts)

When composing a paper, generate the manuscript `.bib` from Scholens citations in the paper directory (not under `.research/`):

```
mcp__scholens__get_paper_citation(document_id="<uuid>", style="APA")
mcp__scholens__resolve_paper_citation(document_id="<uuid>")   # when stored fields are incomplete
```

### Survey & Gap writeback (plain markdown)

After a reading batch, write the narrative to `docs/surveys/<topic>.md` (see § Survey Format) and update `docs/gaps.md`:

```markdown
## G1 — <short title>
- **Description**: ...
- **Source**: <paper title / Scholens document id>
- **Linked ideas**: idea_00X (if any)
- **Status**: open | partially_addressed | closed
```

Gap IDs are sequential (G1, G2, ...). `novelty-ground` and `method-design` read gaps from `docs/gaps.md` instead of a local gap graph.

## Survey Format (`docs/surveys/<topic>.md`)

```markdown
# <Survey Title>

> Generated <date> from the Scholens project "<state.project>"

## Scope
{what question this survey answers}

## Papers
{bullet list: title — one-line takeaway; paper ids are Scholens document ids}

## Themes
{clusters of findings, contradictions, open threads}

## Open Questions
{questions the literature raises but does not answer — seed points for ideas}

## Failed Approaches / Banlist
{methods tried and failed, with reason — never prune}
```

## Error Recovery

| Situation | Action |
|-----------|--------|
| Scholens MCP missing / unreachable | State that literature steps need the Scholens MCP and skip them; do not fall back to a local library. |
| Project title not found on `list_projects` | Create the project (title = `state.project`) and update `docs/scholens-project.md`. |
| Multiple projects with the same title | Pick the most recently updated; if still ambiguous, ask the user. |
| Binding id gone (project deleted) | Re-create the project and re-record the binding. |
| Duplicate ingest | Server resolves duplicates; if you need the existing document id, list project papers and match by title. |
| Legacy `.research/literature/` exists | Treat as read-only archive; copy any needed survey into `docs/surveys/` manually on request (no auto-migration). |
| Research-output tool error (schema) | Do not use research-output / data-table tools; use annotations + search instead. |
